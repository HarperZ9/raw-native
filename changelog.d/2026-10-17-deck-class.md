- **Steam Deck class checks** (RELEASE-PLAN N3 criterion 5, `.github/workflows/deck.yml`). At 1280 x 800 on lavapipe, the Linux build draws raw-hero verified, with the GPU frame equal to the CPU frame byte for byte. It presents the N2 frames, which equal the offscreen and D3D12 WARP frames, and the size and offset controls fail as they should. raw-hero's CPU frame is identical from GCC and from MSVC under Wine. The Proton route (DXVK's dxgi and vkd3d-proton's d3d12) opens no device on lavapipe, because DXVK 3.1.1 needs `VK_KHR_load_store_op_none`. CI keeps this as a recorded miss that passes only for that cause. With Wine's dxgi instead, the D3D12 build renders correctly through vkd3d-proton, but presenting crashes inside Wine. Frame time on Deck hardware is not measured. Bounds: `evidence/n3-deck-class-bounds.json`.
